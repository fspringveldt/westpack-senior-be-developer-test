# Savings Account API

A REST API for creating and retrieving savings accounts with validation, persistence, Redis caching, and containerized local dependencies.

## Quick start

### Prerequisites

- Docker and Docker Compose
- Java 21
- Optional: Gradle 8+ (the project includes the Gradle wrapper)

### Local setup

#### macOS

Install Java 21 if needed:

```bash
brew install openjdk@21
```

Then add Java to your shell environment:

```bash
export JAVA_HOME=/opt/homebrew/Cellar/openjdk@21/21.0.12
export PATH="$JAVA_HOME/bin:$PATH"
```

#### Windows

Install Java 21 from Adoptium or Oracle, then add it to your PATH in PowerShell:

```powershell
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-21"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
```

If you prefer a permanent setup in Windows, add `JAVA_HOME` in System Properties and ensure `%JAVA_HOME%\bin` is in PATH.

Start the supporting services:

```bash
docker-compose up
```

Run the app:

```bash
./gradlew bootRun
```

On Windows PowerShell:

```powershell
./gradlew.bat bootRun
```

Open the app locally:

- API base: http://localhost:8080/api/v1/savings-accounts
- Swagger UI: http://localhost:8080/swagger-ui.html
- OpenAPI spec: http://localhost:8080/v3/api-docs
- Health check: http://localhost:8080/api/v1/actuator/health

## What this project does

- Creates savings accounts with system-generated IDs
- Enforces a per-customer account limit
- Validates account nicknames against a configured offensive-word list
- Uses Redis for GET caching with database fallback
- Exposes RFC 7807-style error responses
- Runs database migrations with Flyway

## API at a glance

### Create account

```http
POST /api/v1/savings-accounts
Content-Type: application/json

{
  "customerName": "Ada Lovelace",
  "accountNickName": "Rainy day fund"
}
```

**Browser console:**

```javascript
fetch("http://localhost:8080/api/v1/savings-accounts", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    customerName: "Ada Lovelace",
    accountNickName: "Rainy day fund",
  }),
})
  .then((r) => r.json())
  .then((data) => console.log(data));
```

Returns `201 Created` with the created account payload.

### Get account by ID

```http
GET /api/v1/savings-accounts/{id}
```

**Browser console:**

```javascript
fetch("http://localhost:8080/api/v1/savings-accounts/{id}")
  .then((r) => r.json())
  .then((data) => console.log(data));
```

### Get account by account number

```http
GET /api/v1/savings-accounts/by-account-number/{accountNumber}
```

**Browser console:**

```javascript
fetch(
  "http://localhost:8080/api/v1/savings-accounts/by-account-number/{accountNumber}",
)
  .then((r) => r.json())
  .then((data) => console.log(data));
```

### Common response codes

- `200 OK`: account found
- `201 Created`: account created
- `400 Bad Request`: validation failed or malformed request
- `404 Not Found`: account not found
- `409 Conflict`: customer limit reached
- `503 Service Unavailable`: database temporarily unavailable

## Core business rules

### Validation

- Customer name is required and trimmed before validation
- Account nickname is optional but must be 5–30 characters when supplied
- Invalid or hostile values return a `400` response

### Account limits

- Default limit: 5 accounts per customer
- Matching is case-insensitive
- The limit is enforced before persistence and protected by database constraints under concurrency

### Offensive nickname filtering

Nicknames are normalized before matching, so evasive values like `B_a_d Word` are caught as `badword`.

### Identifier design

- internal ID: UUID
- customer-facing account number: UUID string
- both are generated by the system and immutable after creation

## Configuration

Edit [src/main/resources/application.yml](src/main/resources/application.yml) for runtime settings such as:

- account limit
- offensive nickname list
- database config
- Redis config
- actuator endpoints

Example:

```yaml
savings:
  account:
    max-accounts-per-customer: 5
    offensive-nicknames:
      - badword
      - offensive
      - inappropriate
```

## Architecture overview

### Layer layout

- `api`: REST controllers and centralized error handling
- `service`: business logic and validation policies
- `domain`: JPA entity and repository
- `config`: cache, policy, and OpenAPI setup

### Design highlights

#### Immutable domain model

The `Account` entity is intentionally immutable after creation. This makes the state easier to reason about and avoids accidental mutation.

#### Cache-aside with graceful fallback

Read traffic is cached in Redis. If Redis fails, the application falls back to PostgreSQL without failing the request.

#### Database-backed consistency

The account number is unique, and the account limit is enforced with a database-aware check to avoid race-condition issues under concurrency.

## Troubleshooting

### PostgreSQL not starting

```bash
docker-compose ps postgres
docker-compose logs postgres
```

### Redis not responding

```bash
docker-compose exec redis redis-cli ping
```

Expected response: `PONG`

### Validation or moderation mismatch

- check the nickname length after trimming whitespace
- check the configured offensive terms list
- use Swagger UI to reproduce the exact request quickly

### Windows troubleshooting

#### `JAVA_HOME` is not recognized

```powershell
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-21"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
```

If Java still is not found, verify the installation path and reopen the terminal.

#### `gradlew.bat` fails because the shell cannot find Java

```powershell
java -version
```

If this fails, Java is not on the system PATH. Install JDK 21 and ensure `%JAVA_HOME%\bin` is included in PATH.

#### Docker is installed but containers do not start

```powershell
docker --version
docker-compose --version
```

If these commands fail, install Docker Desktop and restart the machine before running the app.
